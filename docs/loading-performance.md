# Workspace loading

The business screen now displays an authorized local snapshot before checking the shared folder. Existing rows remain visible during that check. A single `/api/business/workspace` response contains records, history and synchronization state; audit and quarantine data are included only for their corresponding views. Audit access still requires an administrator.

The response fingerprint covers the actual local data, including unpublished edits. When it matches the client's last accepted fingerprint, the server omits the data arrays. The page retains its current arrays and updates synchronization status only as necessary. Requests are bound to the initiating workspace, and superseded responses cannot overwrite a more recent refresh or save.

Background synchronization still acquires the shared lock and verifies the current team/device permissions. It may skip snapshot ingestion only when the same process previously completed ingestion, the validated shared HEAD is unchanged, and there are no pending operations, deletion imports or conflicts. Errors invalidate this cache. Background checks perform full validation again after five minutes; explicit refresh/sync and maintenance continue to perform full checks. A newly started process always performs full ingestion first. Corruption of an unchanged snapshot or cached attachment may therefore be detected at the next full check rather than each background poll.

No database schema, shared protocol or backup format changes are required. Existing write version checks, conflict handling, paused-session rules and permanent-deletion protection remain in place. Local-first display can briefly show the last synchronized state until the shared check finishes, and still requires a current access check (with the existing offline fallback).

Validation includes unchanged polling, local/remote edits, conflicts, revoked membership, rollback and malformed HEAD detection, failed attachment retry, periodic and explicit full validation, delayed shared synchronization, paused sessions, remote deletion, stale workspace requests and out-of-order UI responses. Actual latency over the team's Windows network share still needs acceptance testing; local tests do not establish a speedup percentage.
