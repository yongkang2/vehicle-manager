# 车辆数据管理使用说明

应用版本以“版本与下载”窗口和发布包为准。请从 [GitHub 最新正式版](https://github.com/yongkang2/vehicle-manager/releases/latest) 下载；版本沿革与交付规则见 [发布说明](releases.md)。

当前检出的源码为 **1.6.0 开发版本，尚未正式发布**。下述“车辆改装”新流程说明当前开发源码，不代表 GitHub 已提供对应正式包，也不代表真实 SMB 多机验收已完成。

## 启动和同事加入

1. 将便携 ZIP 完整解压到本机可写目录，双击 `Start.cmd`。无需同事运行 npm；端口占用时会自动选空闲端口，以启动后打开的网址为准。
2. 首次注册自己的本地账号。默认英文，右上角可切中文。登录及注册页底部显示“开发者：TA98755”致谢，该标识不代表账号或权限。
3. 填写已有的 Windows SMB 共享路径并测试。文件夹没准备好可稍后配置，程序不会创建远程根目录。
4. 负责人在专用空目录明确创建团队，成为首位管理员。同事必须选择同一已有团队并申请加入，不能每人创建一个团队。
5. 管理员在“团队权限”核对姓名、设备后批准；普通新同事建立独立团队身份，同一人增加电脑才绑定已有身份。
6. 本机数据默认保存在 `%LOCALAPPDATA%\VehicleManager\data`，与程序解压目录分开。首次启动会查找当前目录或相邻旧版 `vehicle-manager-*` 目录中的 `data/`，先校验复制，再将旧目录改名为 `data.migrated-backup-*`。更新前先用旧版 `Stop.cmd` 停止服务并另做冷备份；旧版仍运行时新版会拒绝迁移。若检测到多份旧数据（例如 Downloads 里留了多个解压目录），程序自动采用最近使用过的那份并在窗口打印被忽略的目录，也可在 `data/.data-migrated` 中查看来源；若那份不是权威数据，请停止服务后把正确的 `data/` 放进新版目录，或用环境变量 `VEHICLE_MANAGER_DATA_DIR` 指定目录再启动。不要把设备数据复制到另一台电脑。
7. 服务每 5 分钟检查一次应用页面连接；全部应用标签页或浏览器关闭后会自动安全停止，并为刷新、页面重连保留短暂宽限期。仅切换标签页、最小化或一段时间不操作不会停服务；还有其他应用标签页打开时也不会停止。启动后始终未打开应用页面的服务，也会在首次 5 分钟检查时退出。自动停止后请重新双击 `Start.cmd`；需要立即停止、搬目录或升级时仍可使用 `Stop.cmd`。停止时会等待正在进行的同步结束，离线修改仍保存在本机待同步队列中。不要同时手动运行多套服务去打开同一本地数据库。

公司程序管控和共享权限仍然有效。软件不保存 Windows 密码；Windows 当前登录账号须先有共享和 NTFS 权限。真实公司网络需先进行多机测试。

## 程序版本与手动更换

程序不提供自动检查、下载或安装更新。“版本与下载”显示当前版本，并提供 GitHub 项目和发布包链接。

1. 更换版本前保存工作，用旧程序对应的 `Stop.cmd` 停止服务，独立备份本机数据及团队共享目录。
2. 手动下载并完整解压新发布包，在新目录运行 `Start.cmd`；保持原本的数据目录设置，无需重新注册账号。
3. 确认版本、账号和原有数据后再移除旧程序目录。不要同时运行新旧程序访问同一份数据，也不要删除本机数据或团队共享目录。
4. 团队最低客户端版本限制继续有效；它只限制兼容性，不负责下载安装。团队成员应协调更换版本。
5. 如果旧版自动更新仍在运行，先等待或处理旧版更新流程；新版不会绕过旧版更新锁打开数据库。

开发者通过 `npm run package:portable` 生成便携包并上传 GitHub Release；发布包不再包含自动更新脚本。

## 团队成员与设备

- 在线管理员进入“团队权限”，默认显示“成员与设备”。每行对应当前团队的一位成员，显示团队昵称（未设置时显示姓名）、真实姓名、角色、启用状态和已批准设备数量；可按姓名、昵称、成员标识或设备名称及标识搜索。
- 点击成员行左侧展开箭头，查看该成员绑定的设备名称、完整设备标识和本地账号标识。设备绑定依据是“设备标识 + 本地账号标识”，同一人使用多台电脑时保留同一个团队成员身份。
- 在“加入申请”核对申请人和设备。新成员选择“创建独立的团队身份”；已有成员新增电脑时选择其现有身份，批准后只增加设备绑定，不重复创建成员，也不改变现有角色。不会仅凭同名自动合并；同名时核对成员标识。
- “编辑成员”可修改团队昵称、真实姓名、角色和启用状态。真实姓名必填，昵称可留空，两项最多各 60 字；只修改本团队资料，不修改本地登录用户名、账号姓名或密码。旧成员没有昵称时继续显示原姓名。
- 在展开的设备行点击撤销图标可单独撤销该设备绑定，其他绑定不受影响；停用成员则会阻止该成员所有设备访问团队。已撤销的设备仍保留显示，不能通过重新申请自动恢复。
- 批准、拒绝、编辑成员和撤销设备均须填写操作原因，并记录到“管理历史”。不能停用、降级最后一位有效管理员，也不能撤销其唯一获批设备。

## 个人入口与团队切换（第一版）

1. 电脑端点击左下角姓名／头像，打开“个人工作空间”；手机端点击顶部个人图标。团队连接、选择、撤回申请、断开会话和恢复同步都在这里，不额外占用左侧业务导航。
2. “连接其他团队”可选择已有共享文件夹申请加入，或在专用空目录创建团队。本地账号不变，不同团队分别审批权限、保存车辆、原件、历史、待同步修改及冲突；不会跨团队提交。账号资料及密码修改、永久删除工作空间不在本版范围内。
3. “进入团队”只切换当前登录会话。同一浏览器普通标签页共用登录状态；切换或重新登录后，旧标签页提交会被拒绝，需重新加载。页面顶部显示当前团队，导入和编辑前先核对。其他独立登录会话可以选择不同团队。
4. 有未同步修改或冲突时，需确认将它们保留在原团队才能切换；返回有积压修改的团队后默认暂停同步，核对后在个人入口确认“恢复团队同步”。暂停期间不能打开永久删除预览、确认删除或恢复业务备份；下载备份、只读查看及导出隔离操作仍按原权限开放。其他正在使用同一团队且启用了同步的会话仍可能同步该团队队列。
5. 原共享目录删除、失联时，也可“断开当前会话连接”再连接其他团队，不清空旧数据、不撤销成员资格。仅移动了完整原团队目录时，连接原团队的新路径即可，程序按团队标识识别，不按名称认定。
6. “撤回加入申请”需要原共享目录可用，并且申请仍待审批；已批准的申请不能通过此按钮撤销权限。目录不可访问时不会显示撤回成功，远端申请仍可能获批，应联系原管理员处理。本机断开不是远端撤回。

### 升级与数据保护

- 应用版本统一由 `package.json` 管理；当前 1.6.0 开发源码的本地数据库结构版本为 **6**。首次使用前停止旧程序，并独立备份整个本地数据目录。升级会检查实际表和字段，兼容此前两种互不相同的版本 3 结构（个人工作空间／目录与会话结构，或永久删除／隔离结构）、版本 4／5 及其他受支持的旧结构；补齐缺少的结构，保留身份、会话、团队选择、车辆、队列、冲突、删除回执及隔离操作。
- 修改已有数据库前，先在该数据库所在目录生成并校验 `migration-backups/before-schema6-<uuid>.sqlite`，再事务化升级；备份失败不会继续。`data/workspaces/` 中的已有团队数据库在首次打开时也分别执行同样的备份与结构检查。新建空数据库无需升级备份；已有数据文件和目录不搬迁。
- 原团队仍使用原数据库和原件位置，不搬动旧记录；后续团队数据位于 `data/workspaces/`。保留整个目录，不要单独复制某个数据库或删除 WAL 文件。
- 升级备份含本地账号凭据、会话等敏感信息，且不包含单独存放的原件文件，不可分享，也不能替代完整独立备份。
- 旧版程序无法直接打开新版结构。需要回退时，先停止服务并保存所有新版数据，再由维护人员恢复完整升级前备份；不要用单个旧数据库覆盖当前工作目录。

## 车辆与控制器

### 配置版本

- “配置版本”最初在应用 1.3.0 引入。全体协作安装统一升级后，由管理员为当前工作空间一次性启用；共享业务格式至少为协议 3，已启用的更高协议不会降级，旧客户端无法向不支持的格式发布。团队名册及已有升级策略保持不变。车辆初始没有已发布配置，已批准成员在联网且当前会话已启用同步时审核并发布，按车辆身份依次获得 R01、R02、R03。
- 先在高压电池、电驱电机、控制器和热管理页签维护工作数据，再创建版本审核。热管理系统类型继续沿用车辆原字段。管理员可新增使用通用标识字段和说明的组件类型，并重命名自定义类型。纳入核对的类别会记录所有在用实例，包括多电池、多电机及历史额外控制器。
- 在“组件类型”中，管理员可停用、移除和恢复任何类别，包括四个内置类别。该策略最初在应用 **1.3.0** 引入；首次修改前须统一升级协作客户端，该次修改会原子提升至至少共享业务协议 **4**，已启用协议 5 时保留。停用类型仍显示在管理列表，移除类型可通过“显示已移除”查看并恢复；启用或恢复后沿用原类型身份。每次修改需填写原因并最终确认一次，内置类型名称和字段固定。
- 策略仅影响未来配置版本核对：车辆页签、在装组件记录和编辑功能仍可使用，不会物理删除记录。策略启用前，旧版停用自定义类型的新增限制继续适用。调整适用类别的包含范围后会提示“配置有未发布更改”，之后修改被排除类别的组件不会触发提示。核对中明确列出不纳入的类别，至少包含一个部分才能发布。旧版本保持不变，新快照冻结核对范围；比较与复制摘要会区分“不纳入配置核对”和实物拆除。历史策略备份采用格式 4、字段版本 3；当前开发源码导出格式 5、字段版本 4，仍可读取格式 1–4，恢复不能覆盖当前目录策略。当前本地数据库结构版本为 6。
- 审核自动填入已有值。必填关键信息缺失时，需选择“未知”或“不适用”并说明原因；缺少整个组件部分时，需确认“未安装”或“未知”并说明。说明只保存在冻结的版本快照中，不改写组件普通字段或 DOVE 原始观测。填写变更摘要，可选填标题，最后一次点击“发布配置版本”。取消审核不产生版本，已经单独保存的组件修改仍然保留。离线可维护组件，暂停同步时请先在个人工作空间明确恢复同步后再发布。
- 已发布版本只读，保留 VIN、人员、时间及组件身份和详情，可比较版本或复制摘要。概览及可选的“配置版本”列表／CSV 列显示当前 R 编号；相关组件修改后提示“配置有未发布更改”。负责人、位置、照片、保存计数及相同配置的 DOVE 重导入不触发该提示。纠正内容需发布下一个版本，不能改写旧版本。
- 当前业务备份格式 5 保留冻结版本、组件类型、改装关联及文件和持久发布回执，并兼容格式 1–4。历史格式 4 已支持配置版本数据。恢复旧工作数据不会归档或覆盖已发布版本、回退最大 R 编号，或用旧名称／启用状态覆盖当前组件类型。合法的缺失历史会与工作数据一同排队，在共享锁内发布；不可变内容冲突、编号重复或链条断裂时拒绝恢复。已永久删除车辆的旧身份及其版本仍会跳过；用相同 VIN 新建的车辆拥有独立的版本序列。

- “列设置”支持档案概览中的所有带标签车辆字段，包括“排放合规等级”。可单独添加“昵称”“VIN”“车牌有效期”，同时保留现有车辆与车牌组合列；“冷却架构”可展示旧数据中已有的值，但不会恢复到车辆编辑表单。这五列默认隐藏，沿用个人列顺序、列宽及表头筛选设置，原十列默认布局不变。车辆照片及其附件引用不属于可选列。

- 点击车辆数据列表的表头筛选按钮，可搜索并勾选完整单元格内容，包括“（空白）”，再点击“应用”。“重置”清空勾选，应用后移除该列筛选；未应用直接关闭时保留原筛选。同列多个值满足任一即可，不同列与上方搜索、状态及归档条件需同时满足。选项覆盖“显示已归档”所允许的全部车辆，不受分页或其他筛选限制。昵称/VIN、车牌/到期日、更新时间/版本以及多个电池的组合内容各作为一个选项。已筛选表头会高亮，可用“清除列筛选”统一清除。隐藏列会清除该列筛选，调整顺序或宽度则保留。当前账号、工作空间内切换页面时保留筛选；刷新网页、退出登录或切换工作空间后清除。离线和暂停同步时也可使用，不保存为个人布局、不产生业务更改，也不改变导出配置。

- 在“列设置”中启用“VCU 类型”，可在车辆列表以普通文本显示“控制器 → VCU → 类型”的值。该列默认隐藏，初始宽度 160 像素，沿用个人列的显示、排序和宽度保存设置。它与“控制器”页签中的 VCU 条目使用同一未归档控制器，兼容 EVCU 别名；未录入 VCU 或旧类型为空时显示 `—`。修改 VCU 类型后，重新加载记录即可更新列表。此列为关联数据显示，不新增车辆字段，也不需要数据迁移。

- 车辆列表的表头和内容居中显示。在“列设置”中可显示、隐藏及调整已有字段的顺序，车辆始终在最前，操作始终在最后且不能隐藏。默认列之外可添加车型、颜色、热管理系统类型、其他说明、高压电池零件号及序列号。拖动表头右边缘可调整列宽，双击恢复默认宽度；聚焦列边缘后可用左右方向键、Shift 加大步长及 Home/End 调整。布局自动保存到当前工作空间的本地账号，记住隐藏列的宽度，重启后仍保留；请留意保存状态，失败时点击重试。“恢复默认布局”恢复原十列及默认宽度。这些个人设置不参与同步或业务备份，也不影响 CSV 导出模板。
- 点击操作箭头，在档案概览中查看或上传车辆封面照片。已批准成员可上传、更换或移除封面，需填写变更原因并通过版本检查；已归档车辆只读。支持 JPEG/PNG，最大 10 MB、单边 8,192 像素、总计 2,400 万像素，不裁剪或清除原文件元数据。更换或移除封面只改变概览展示，原附件、文件、历史及已有备份仍保留。照片沿用附件同步，离线或暂停同步时可排队保存，不会自动恢复团队同步；所选照片不可用时不会自动替换为其他附件。业务备份保留照片引用及附件，旧备份恢复后无封面。本功能不升级数据库、共享协议或备份格式，请一同升级协作客户端。
- 已批准成员登录后进入“车辆总览”，可新增真实车辆。VIN 必须合法且唯一；项目代号与车型分开。
- “实际位置”为选填自由文本，可在新增或编辑车辆时填写、修改或清空；车辆列表与详情均显示，搜索也包含位置。已有车辆可暂留空；请同步升级各协作客户端，以便大家都能查看和维护该字段。
- 手动新增或编辑车辆时，“排放合规等级 / Compliance Level”为必填下拉框，须明确选择 `Eu7`、`CN6`、`Eu6` 或 `PL8`，没有自动默认值。档案概览在热管理系统类型之后显示该值；搜索、历史、同步、JSON/CSV 导出及业务备份均保留。旧车辆未分类时显示 `—`，下次手动保存须补填；仅更改照片、归档、DOVE 导入或恢复旧备份不会强制分类。本功能不升级数据库、共享协议或备份格式，请一同升级协作客户端以免旧编辑器丢弃新字段。
- 点击车辆进入详情，维护基本信息、控制器、车辆改装、车载设备、DOVE、附件和历史。
- “附件”支持 `.xlsx`、`.xls`、`.pdf`、`.png`、`.jpg`、`.jpeg` 和 `.jfif`，队列最多 8 份文件，单份最大 10 MB。可一次多选，核对或移除队列条目后点击一次“上传”，系统逐份提交，无需再次确认。每份文件分别显示结果，无效文件不会阻止其他有效文件上传；已成功的文件保留，“重试失败文件”仅提交明确失败的条目。如果响应丢失，请先刷新并核对附件列表，再清除结果未知的条目并重新选择文件，系统不会自动重试未知结果。关闭抽屉、更换车辆或工作空间、退出登录时停止尚未提交的文件；服务器已接收的上传可能在原工作空间完成。扩展名不区分大小写，文件内容签名须符合支持的格式；JFIF 沿用 JPEG 校验，下载、同步及备份均保留原文件名和字节。离线或暂停同步时沿用现有附件行为，不会自动恢复同步。车辆封面照片使用独立的 JPEG/PNG 上传控件。
- 控制器页签固定展示 VCU、MCU、BMS/MSB，每种只有一个，不提供新增、安装、拆除或位置管理。报告中的 EVCU 对应 VCU，BMS、MSB、BMS/MSB 对应同一 BMS/MSB，忽略大小写和首尾空格。
- 档案概览仅展示车辆基本资料。控制器页签显示控制器名称、类型、供应商、产品零件号、软件零件号、标定版本。软件零件号对应报告的“软件 / 标定零件号”。点击“更多”手动编辑，名称固定；名称之后的“类型”必须明确选择 `Open ECU` 或 `Close ECU`，没有自动默认值。填写变更原因后保存，取消不写入。未录入的控制器也可在此填写，不会新增第二个同类控制器。DOVE 导入及“更新车辆配置”保留已有类型，也可生成未分类控制器；下一次手动编辑保存时必须选择类型。
- 十二字段为：名称、说明、诊断网络、供应商、功能零件号、产品零件号、软件标识 / 版本、软件 / 标定零件号、标定版本、刷写日期、生产日期、序列号。序列号按文本保存，前导零不丢失。
- “高压电池”包含零件号、序列号、零件成熟度及“寿命状态”。每次手动新增或编辑保存必须明确选择 `BOL`、`2Y Aged`、`8Y Aged`、`10Y Aged`、`15Y Aged` 或 `EOL`，中英文界面中的选项文本相同。旧记录没有自动默认值，列表显示 `—`；单独记录拆除、归档及备份恢复不强制补填。新增的控制器类型及电池寿命状态独立保存，不改变旧 `type`、`batteryStatus` 内容；历史、同步、JSON/CSV 及业务备份均保留，CSV 可选择“控制器类型”“寿命状态”，已有模板不会自动增加列。旧备份仍可恢复为空分类。本功能不升级数据库、共享协议或备份格式，请一起升级协作客户端，避免旧编辑器丢弃新字段。
- 未录入的控制器显示为空。旧部件记录及变更历史不会物理删除；遇到历史重复控制器时需先核对处理，程序不会任意合并。
- 保存需填写变更原因。别人更新过同条记录时，重新加载并核对，不反复提交旧版本。
- 归档和恢复由在线管理员执行，归档本身保留车辆、原件和历史。另有“删除车辆”用于移除已归档车辆的工作数据，规则见下节。

## 车辆改装（Vehicle Modification）

- 原改装页签现名为“车辆改装 / Vehicle Modification”。每条记录包含名称、说明、安装／拆除日期，以及选填的“申请人 / Requestor”和“负责人 / Lead”；这两个字段只属于车辆改装，不属于独立的“车载设备”流程。启用新功能前，已有文字记录仍可使用。
- 所有协作客户端升级至兼容版本后，由在线管理员在当前会话明确恢复同步，再点击“启用改装文件及共享”并填写原因。此操作将共享业务协议升级至 **5**，旧客户端无法向该格式发布；不会同时自动启用配置版本或组件审核策略。当前开发源码支持业务协议 **1–5**，后续同步及恢复不会降级已有协议。
- 先保存改装记录，再展开详情添加文件。每批最多 **8 份**，单份最大 **10 MB**，仅支持 `.doc`、`.docx`、`.txt`、`.xls`、`.xlsx`、`.pdf`、`.eml`、`.msg`、`.7z`、`.zip`。核对队列、填写原因后上传；保留原文件名及字节，结构校验不会执行文件内容。文件归档及恢复由管理员操作。
- 点击“应用到其他车辆”，输入已有 VIN 的任意片段搜索，明确选择当前团队符合条件的目标车辆；每次最多 **100 辆目标车**，不会自动预选车辆。选择“一次性复制”或“已关联 / Linked”，核对车辆及有效文件数量，填写一个原因，最后点击一次“应用”。一次性复制为每辆目标车建立当前字段、日期及有效文件的独立副本，之后互不影响。关联模式共享全部字段、日期及文件，包括申请人和负责人；在任意关联车辆修改，都会影响审核中列出的所有关联车辆。
- 创建关联、编辑关联记录或其文件、解除关联及关联归档必须联网，并在“个人工作空间”明确恢复团队同步；操作不会自动恢复暂停状态。先同步待处理修改并解决冲突，记录变化后刷新核对再提交。独立记录编辑及一次性复制继续沿用允许的离线排队行为。
- “解除关联并保留独立副本”仅将本车当前字段、日期及文件冻结为独立记录。归档关联改装或其车辆时，仅为本车保留独立归档副本，其他车辆继续共享；恢复副本或车辆不会自动重新关联。永久删除一辆车仅移除其成员关系，不删除其他车辆使用的共享记录及文件。
- 响应丢失时，重试同一操作，或先刷新核对保存结果，再开始新操作；记录或共享组版本已变化时，重新核对后提交。

## 管理员删除已归档车辆

- 先归档车辆，再由当前团队已启用同步的在线管理员在车辆详情中点击“删除车辆”。普通成员、离线状态和未归档车辆不能执行删除；同步暂停时，先在“个人工作空间”核对保留修改并确认“恢复团队同步”，才能预览或确认删除。
- 核对五分钟有效的预览及全部关联记录数量，输入完全一致的 VIN、`DELETE` 和删除原因后确认。取消不写入；目标有待同步修改或冲突时先处理，预览后车辆或关联记录变化时需重新预览。
- 删除会从当前工作数据中移除车辆及其全部控制器/部件、改装、设备、报告和附件，包括已归档的关联记录。历史、已有备份、共享旧快照和原始文件不做物理清除，这不是安全擦除功能。
- 删除先提交共享目录，再刷新本机。响应丢失时可重试同一请求；提示“已提交、待本机刷新”时应再次同步，不要重复创建新的删除请求。
- 永久删除标记阻止旧电脑、离线修改和旧备份恢复旧记录。相关离线操作及文件会保留在“共享同步”的隔离区，可查看和导出，但不能选择“保留本地值”让车辆复活。
- 删除后允许使用同一 VIN 新增另一个车辆身份；旧数据不会自动恢复。重新预览 DOVE 后可向新车辆留存同一原件，旧预览不会自动改绑新车辆。
- 首次使用删除、配置版本或改装文件及共享前，停止其他客户端，分别备份共享目录和各电脑本地数据，并统一升级所有协作客户端。应用版本独立于结构和协议版本；当前 1.6.0 开发源码将受支持的旧本地数据库升级至结构版本 **6**，旧程序不能打开升级后的本地目录。支持共享业务协议 **1–5**：删除可从协议 1 升级至 2，配置版本启用至 3，首次组件审核策略更改至 4，管理员启用改装文件及共享至 5；已有更高协议不会被这些操作降级。业务备份使用格式 **5**、字段版本 **4**，仍可读取格式 **1–4**。团队名册与既有升级策略独立。旧客户端可能显示共享快照错误或离线，须升级程序，不要回退 HEAD 或删除共享文件。离线缓存需在升级后重新同步才会移除。

## DOVE

1. 在“DOVE 导入”可一次选择最多 8 份受支持的 `.xlsx`，每份最大 10 MB，点击“上传并预览”。每份文件单独显示结果，某份解析失败或 VIN 未匹配不会阻断其余文件。
2. VIN 从工作簿已识别的摘要和表头读取，不使用文件名或同批文件猜测。有效 VIN 未匹配时，先在车辆总览登记对应车辆，再重新预览；格式错误或相互冲突的 VIN 仍会拒绝导入。
3. 匹配成功后弹出“确认导入”，按文件展示车辆、VIN、采集时间，以及 VCU、MCU、BMS/MSB 的完整十二字段和当前值。核对来源后点击“确认导入”，才会保存报告和原件，并同时录入全部有效控制器字段；取消不会写入。关闭后也可点击“核对导入”重新打开。
4. 在“报告档案”回看、下载原件或选择同一车辆身份、同一报告 VIN 或人工确认 VIN 的两份报告对比；同一车辆内的重复字节内容不会重复留存。
5. 在车辆“控制器”页签点击“更新车辆配置”，选择该车辆已匹配、已留存的 DOVE 报告及控制器，核对当前值和报告值，勾选需要更新的字段并填写原因后保存。也可从报告打开同一更新功能；不需要另外创建控制器。
6. 核对当前值和报告值，默认勾选有效的差异字段；空值、`invalide` 等占位值不能用于覆盖。报告同时有 BMS、MSB 时，可更新字段完全相同的条目合并显示；数据不同则提示人工选择来源。使用早于当前来源采集时间的报告时，必须额外确认。
7. VIN 自动匹配的报告默认勾选“同时录入控制器配置”，可取消勾选以仅留存原件。来源冲突须选择报告条目，旧报告须额外确认后才能录入。缺少的控制器、空值和无效值保留现有数据。重复原件不会新增报告，但每次重新导入均可手动确认重新录入配置。导入及字段更新记录来源报告和变更历史，不改变车辆基本资料和状态。
8. 工作簿确实未提供 VIN 时，在同一个导入窗口中选择车辆并核对选项。按昵称、VIN 或车牌搜索当前团队的已有未归档车辆，每份报告独立选择，不会预选或在窗口中新建车辆。选择车辆后自动刷新预览，不再额外点击关联确认或勾选报告归属确认。此类报告默认仅留存原件，明确勾选“同时录入控制器配置”才更新配置；若显示旧报告警告，最后一次“确认导入”同时确认采用这些旧值，无需另勾确认框。
   窗口显示本次将导入数量，点击一次“确认导入”保存已准备完成的报告，未选择车辆的文件继续保留待处理。提交前取消不会导入；失败文件保留在窗口中供修正，已成功文件不重复提交，部分成功后取消不会撤销已保存报告。更换车辆会清除旧关联确认并重新默认仅留存原件。
9. 人工关联不会修改工作簿原件或补写报告原始 VIN；关联车辆身份、VIN、操作人和时间另外记录并随同步及备份保留。报告窗口会提示“VIN 缺失，车辆由用户手动选择”。CSV 的报告原始 VIN 保持空白，车辆 VIN 是独立字段。重新选择会使旧确认失效；归档、删除或 VIN 变化需重新核对，不会按相同 VIN 自动改绑新登记车辆。此功能不升级本地结构、共享协议或备份格式，协作客户端应一起升级。

差异不等于升级正确或故障已修复。故障列表和两报告差异可查看，但不统计累计发生次数，不做长期趋势和自动根因分析。已知模板以外的工作簿可能被拒绝；超时、解压规模和数据量也受安全限制。

## 同步与冲突

- 当前会话启用同步时，本地保存后立即尝试同步，查询前也会检查共享库，服务每 30 秒重试。暂停的会话需先在“个人工作空间”核对保留修改并确认恢复；永久删除及业务备份恢复不会绕过暂停状态。
- 离线时显示缓存状态，成员可继续保存允许的业务修改；管理员操作需要在线。
- 不同字段可以自动合并；同字段改成不同值时，进入“共享同步”选择本地或共享值并填写原因。
- 重复 VIN 优先保留正确共享车辆，或先改正本地 VIN；不要把本地数据库复制到共享目录覆盖别人。
- “已同步”不代表所有关机电脑都已更新。检查待同步为 0、冲突为 0、无错误提示。
- 团队锁只在共享操作期间持有，不随登录长期占用。竞争时先自动等待最多 3 秒；持有者每 10 秒续期，连续 2 分钟未续期的遗留锁会在后续操作时自动恢复，包括旧版遗留的 owner.json 和未完成初始化的空锁。后台同步仍按正常周期重试，不需要手动删锁。
- 本次锁机制更新必须全员一起升级：先停止所有旧版服务，独立备份共享目录与各自本地数据，再启动新版。旧版没有续期机制，不能与新版安全混用长时间共享操作。截图中的 .saved-* 目录属于保留副本，不是活动锁，程序不会自动删除它们。
- 出现“共享锁已过期或无法验证”时，程序会停止后续共享提交；已完成的提交不会撤销。恢复网络后先同步、核对结果，再重试。永久删除使用原请求编号重试，避免重复执行。电脑休眠后也会重新检查锁，不能凭休眠前的锁继续提交。
- 锁内有未知文件、共享目录缺少删除权限或网络持续异常时，请管理员检查，不要强制删除活动锁。仅使用同一个实际 SMB 共享目录，不要用 OneDrive 等双向同步目录或离线副本代替。文件租约无法提供任意网络分区下的中央事务保证；使用人数和一致性要求继续增长时，应迁移到集中式服务。
- 成员停用、降权或设备撤销后，待提交操作会按最新权限重新判断；不能靠离线旧角色继续提交管理操作。

## 自定义 CSV 导出与个人模板

- 在“车辆总览”点击“导出 CSV”，通过搜索、项目、车型、状态、负责人、实际位置和热管理系统类型筛选车辆。不同筛选项同时满足，同一筛选项的多个值任选其一；可跨分页“选择全部匹配车辆”，也可临时取消个别车辆。
- 分别选择车辆、控制器、车辆改装、设备、报告摘要和附件信息的导出字段，并用上下移动调整列顺序。改装可选申请人、负责人及共享组标识；附件信息可包含改装文件及其改装、共享组和文件标识，CSV 不含原件字节。默认不包含已归档车辆或关联记录，可勾选“包含已归档”；列标题可选英文或中文。
- 下载固定为一个 ZIP，每个勾选类别各有一个 CSV；没有关联数据的类别仍包含标题行。不含原始文件、DOVE 控制器／故障明细、历史车辆快照、变更历史、审计及隔离操作，不能代替业务备份。
- 模板保存筛选条件、类别、列顺序、归档选项和标题语言，不保存本次手动勾选的车辆。应用模板会重新选择当前匹配车辆供核对，不会直接下载；支持保存、另存为、更新、重命名和删除。
- 模板仅属于当前电脑、当前本地账号和团队，重启后仍保留，不会同步给同事，也不包含在业务备份 ZIP 中。
- 导出、刷新导出选择及模板管理只使用本机工作副本，不提交待同步修改，不恢复暂停的同步。离线、有待同步或冲突时需留意窗口提示；需要最新共享数据时应另外执行同步。已知永久删除的身份不会导出，车辆失效或不再符合条件时需刷新，不会按相同 VIN 改绑新车辆。
- CSV 使用 UTF-8 BOM、逗号分隔及标准引号，空值留空，并防止文本被解释为电子表格公式。为保留序列号前导零和长数字编码，在 Excel 使用“数据 → 从文本/CSV”，将这些列指定为“文本”；直接双击可能触发 Excel 自动转换。每次最多选择 20,000 辆车，未压缩 CSV 或 ZIP 数据上限为 200 MiB；超限时请分批导出。导出不改变应用版本、本地结构版本或共享／备份格式。

## 备份和恢复

- 点击“备份数据”先同步团队数据，失败、待同步或冲突时停止，再下载完整业务备份。文件名包含团队、来源和 UTC 时间。本机副本备份仅作为维护接口保留，不显示在日常菜单中。
- 预览会检查原件完整性，可搜索记录并展开字段前后值；一次确认全部归档影响后，输入 RESTORE 和原因执行。恢复前自动生成并回读验证本机数据目录 `restore-backups/` 中的保护 ZIP，失败则停止。副本保留至管理员手动清理，不能替代独立冷备份。
- 在“恢复记录”查询本机恢复状态和保护包 SHA-256。响应丢失后先查询；“本机已应用”可核对并重试共享发布，不会再次应用备份。“未提交业务修改”或“未应用”需重新预览。共享已发布不代表其他电脑已刷新。

- 在线管理员可在车辆总览下载完整业务 ZIP，含车辆、部件、历史、原件、待同步载荷和团队名册快照，不含本地密码及会话。
- 当前开发源码的业务备份使用格式 **5**、字段版本 **4**，包含改装共享组、成员关系、文件、持久回执及保留的恢复载荷，也保留冻结配置版本、组件类型、永久删除标记、隔离操作及其文件；仍可读取格式 **1–4**。历史格式 3／4 及协议 4 策略备份的字段版本 3 继续兼容。恢复时跳过已删除车辆的旧 UUID 及其关联记录，并显示跳过数量，不会复活已删除记录或清除删除标记。旧备份缺失的已发布版本和现有组件类型不会被归档或改写；备份中只属于已删除记录的原件不会重新加入工作数据。
- 改装恢复以共享组和成员关系整体发布；发布前使用比较并交换检查（CAS）核对审核时的基础状态及共享组版本。共享改装已变化时停止发布，保留未发布载荷及关联文件，不覆盖较新的共享修改。在“恢复记录”可“导出保留载荷”，再由已恢复同步的在线管理员填写原因执行“保留并重新审核”，保留本次尝试并刷新共享权威数据，然后重新预览备份。导出的载荷用于人工核对，不会自动重放；旧备份也不能悄悄覆盖或解除现有受管理改装关联。
- 备份未加密，放到受控独立位置，不能只保存在同一共享目录或发到公共聊天。
- 恢复前暂停所有其他客户端和写入，独立备份当前整个共享目录、本地数据并完成待同步操作。
- 当前管理员会话必须启用同步；若处于暂停状态，先在“个人工作空间”核对保留修改并确认“恢复团队同步”。再选择同一团队的备份，输入 `RESTORE` 和原因后提交。软件以前向变更恢复业务，备份以外的现有记录会归档，不做无痕删除。
- 恢复可能覆盖备份后产生的业务修改，不能在别人持续编辑时执行。恢复后验证记录、历史和原件，再让同事恢复使用。
- 普通恢复界面不恢复账号密码、不回退权限或自动重新启用被撤销设备。团队名册丢失或管理账号恢复须单独人工维护。
- 当前备份安全上限为 200 MB，清单 20 MB，单原件 10 MB。没有自动定时独立备份或一键灾难恢复；需由团队安排备份频率和负责人。

## 测试和正式使用边界

本地双客户端、独立进程、已知 DOVE 模板、界面与便携包已做开发验证；真实 Windows SMB 多机、公司安全策略、长期容量和停电网络故障仍需现场验收。

有共享写权限或本机数据库访问权限的人可以绕过正常应用控制，本工具不提供不可篡改审计。离线设备也无法被立即撤回已缓存数据。业务变更历史同步到团队；“本机审计日志”仅展示该设备的登录、下载、导出及备份操作。

遇到错误先保留本地数据和共享快照，记录提示与操作时间，不要删除数据库、重建团队或用旧快照强制覆盖。

### 七天备份提醒

车辆总览菜单仅保留“备份数据”“恢复数据”“恢复记录”，点击后再查看简短说明。在线管理员进入车辆总览、以及页面保持打开时，程序会检查团队最近一次完整备份传输时间；满七天或没有备份记录时提示。任意管理员完成团队备份后更新共享时间；普通成员不弹窗。“今天稍后提醒”在当前电脑上对当前管理员当天不再弹出，次日仍未备份再提示。离线时不根据旧记录提醒，本机导出和恢复前自动保护副本不重置计时。完成传输不能证明浏览器已将文件保存到磁盘；旧版程序不记录此时间，管理员应统一使用新版。
