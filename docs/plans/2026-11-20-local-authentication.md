## 2. 已确定的产品规则

### 2.1 三种身份各自负责什么

| 对象 | 用途 | 权限边界 |
| --- | --- | --- |
| 本地账号 | 在这一安装的数据目录中登录，使用本程序的独立密码 | 注册本地账号不会获得任何已有团队权限 |
| 团队成员 | 团队内的人员身份、角色和业务历史归属 | 由团队管理员核验和批准，保留现有成员 ID |
| 设备绑定 | 某台电脑上的某个本地账号与团队成员的关联 | 换电脑需要独立申请；相同姓名或账号不能自动建立关联 |

“团队已批准”表示项目管理员批准了人员和设备，不表示微软认证、公司人事认证或邮箱所有权认证。Windows 的 SMB/NTFS 权限仍由 Windows 执行，程序不接收公司密码、不获取新的共享权限。

### 2.2 本版包含的调整

1. 登录、注册文案明确“本地账号”和“本程序密码”。账号建议使用工号，但不强制已有用户改名。
2. 新注册只要求姓名、账号和密码，复用现有注册成功后的登录会话与共享目录引导。
3. 加入团队时明确列出管理员要核对的姓名、本地账号和设备信息；待批准、拒绝、撤销设备等状态各自给出准确下一步。
4. 保留管理员选择“建立新成员”或“绑定原成员”的流程，不按姓名、工号或邮箱自动合并。
5. 在个人工作空间新增修改本程序密码的入口。
6. 登录页增加忘记密码的说明入口，解释当前恢复边界，不提供未经身份核验的密码重置。
7. 清理当前分支中的微软身份运行代码、依赖、入口和当前版本的配置说明。
8. 保留所有旧账号、成员 ID、设备 ID、角色、业务历史、已保存待同步修改和冲突。

### 2.3 本版明确不做

- 微软/Teams 登录、Azure 注册、邮箱验证码、Magic Link、外部认证平台或发信服务。
- 新增公司邮箱字段。当前账号模型没有邮箱；不用未验证邮箱增加识别复杂度，更不用它认领成员或找回密码。
- 账号跨电脑自动同步、远程修改其他电脑的密码、账号自动合并、管理员直接重置成员本地密码。
- 改名、修改个人资料、角色体系重构、公司域名白名单、长期免密登录或“记住密码”。
- 更换密码哈希算法、扩展账号字符集、改变账号大小写规则或重新设计整个登录页面。
- 自动恢复密码、恢复码、自动移动旧账号的未同步数据。这些需要独立设计，不能通过新建账号假装找回。

## 4. 登录注册与入组体验

### 4.1 注册

- 姓名继续对应 `displayName`，保持现有 1–60 字符和空白校验。
- 账号继续对应 `username`，保持现有 2–24 字符及文字、数字、下划线、连字符规则。文案可建议使用工号，不把它当作公司验证过的工号。
- 保持现有账号大小写和唯一性语义。只在当前安装内判断重复；不同电脑可以创建同名账号。
- 密码继续使用现有 10–128 字符规则和 `scrypt` 存储。密码原文不得 trim、静默截断或传到共享目录。
- 保持密码显示/隐藏、自动填充和键盘提交。失败保留可修正的表单状态，提交中防重复。
- 明确说明“本程序独立密码，请勿填写公司微软账号密码”。
- 注册成功仍建立本地会话；接下来可以连接团队，也可以沿用“稍后设置”。不自动创建远程团队。

### 4.2 登录

- 保留现有最近账号选择；只保存账号名称，不保存密码。
- 已有账号不需要重注册，账号名不改写成邮箱，不强制改名或修改密码。
- 不增加“永不过期”会话选项，保留当前 8 小时会话策略。
- 显示“此账号属于当前安装的数据目录；换电脑需建立本地账号并由管理员绑定原成员”。
- 登录失败、限流和本地服务不可用沿用现有错误渠道；不把网络故障描述为密码错误。

### 4.3 加入团队与换电脑

- 新申请的 `Identity` 拟增加可选 `username?: string` 快照。此字段从后端已认证的 `req.localUser.username` 取得，不信任申请请求正文提供的账号。
- 共享的只是姓名、本地账号和设备等核验资料，绝不包含密码、盐、哈希或本机会话令牌。
- 账号快照用于申请表和批准对话框的人工核对；不能代替 `deviceId + localUserId` 的现有授权判断。
- 管理员批准默认仍是现有的新成员行为；换电脑时由管理员明确选择绑定原有成员。没有自动匹配、自动批准或默认继承管理员角色。
- 旧申请没有账号快照时显示“未记录”，不根据姓名、当前设备关联或成员资料猜测历史账号。
- 当前成员名、昵称与本地姓名继续分别管理；本次不自动互相覆盖。
- 新电脑首次运行不自动成为已有团队管理员。首次管理员创建只用于明确确认的新空团队。
- 不新增可绕过批准的“绑定公司身份”入口；用户能看到的是本地账号和现有团队批准状态。

## 5. 修改密码的接口与会话规则

### 5.1 拟新增接口

`POST /api/account/password`，只对有效本地登录会话开放。

请求只包含 `currentPassword` 和 `newPassword`。确认新密码的字段只在前端比较，不作为服务端信任依据。目标账号从认证会话获取，不能通过请求中的用户 ID 或角色选择其他账号。

服务端要求：

1. 保留 `X-App-Request`、请求大小限制及本地访问保护；使用现有认证限流，防止重复试旧密码。
2. 正确验证旧密码，再校验新密码长度；使用新随机盐生成新哈希，保持时序安全比较，不引入新的密码库。
3. 新旧密码相同明确拒绝，两个新密码在前端不一致时不发请求。新密码不得截断或去除首尾空格。
4. 修改只针对当前安装的当前账号，不读取共享路径，不要求团队批准、管理员角色、互联网或共享盘在线。
5. 事务内更新密码凭据、撤销该账号全部本机会话并写入本机安全审计；任何失败整体回滚，其他账号的凭据和会话不受影响。
6. 成功清除当前浏览器的登录 Cookie，返回明确的成功与重新登录标志。不得在后台自动创建替代会话或继续使用旧工作空间令牌。
7. 审计记录“账号密码已修改、该账号本机会话已撤销”，不记录任意密码、盐、哈希或完整 Cookie。

接口具体错误码按现有 `AppError` 风格实现：未登录、旧密码错误、非法新密码、限流、在途操作忙分别给出可操作的英中提示。新错误码应在实现中登记到统一字典，不透传数据库或原始异常。

### 5.2 为什么修改成功后重新登录

撤销当前账号的所有本机会话，规则清楚，也避免保留旧密码登录产生的会话。此操作不影响其他电脑上该人员自己的本地账号，因为它们是独立凭据。

- 修改对话框提前说明“成功后需要重新登录，其他本机会话也会失效”。
- 输入旧密码、新密码、确认新密码；提供明确确认，提示先保存或复制尚未提交的表单。
- 密码修改成功后，当前页面主动进入本地登录页，并显示成功提示。密码字段在成功或取消后清空。
- 其他页面或会话下一次请求被拒绝时，复用已有会话变化提示，允许复制未提交内容，不自动重放写请求或偷偷刷新页面。
- 只有确认成功响应才进行前端成功退出；传输中断时说明结果可能已生效，提示重新登录确认，不宣称修改失败或自动重试修改。
- 已保存的离线队列、冲突和文件保持在原目录；修改密码不要求先同步，不恢复已暂停的同步，也不删除待处理数据。
- 再次登录使用现有团队选择和待同步数据复核流程，不新增自动切换或自动恢复同步的捷径。

### 5.3 在途请求与会话撤销

实施时复用 `server/app.ts` 的 `active` / `switching` 状态，以及业务最终会话检查，不建立新的通用锁框架。

- 修改前检查当前账号全部会话是否存在正在执行的受保护业务写入、团队管理或工作空间切换；忙时拒绝本次修改，保留旧密码和会话，提示稍后重试。
- 密码更新和删除会话必须在同一同步事务中完成；不能在二者之间等待网络或文件操作。
- 对已经发出的异步请求核对现有最终会话检查，确保撤销后不能绕过保护再写入。
- 用可控的挂起请求测试真实竞态。若现有请求追踪覆盖不了某条被影响的写路径，先补足该边界再交付，不用仅有前端禁用按钮代替服务端保护。

## 6. 忘记密码与身份恢复边界

第一版提供说明入口，不新增重置 API，不虚构邮件找回。

说明应引导用户核对最近账号和正确的数据目录、查找自己保存的本程序密码，并解释团队管理员不能直接读取或重置本地密码。

若确实无法登录，需要人工评估本机保留的账号、文件、未同步修改和备份。新建账号再由管理员绑定原团队成员，只能解决后续团队访问，不能宣称恢复了旧账号，也不能自动搬走旧账号的数据。界面不提供一键删除/重建本地账号、清空数据库、免验证重置或覆盖业务备份的建议。

管理员仍可通过已有流程禁用团队成员或撤销设备。离线撤销的延迟与共享目录的现有信任边界保持不变，不承诺公司离职状态实时生效。

## 10. 必须通过的验收

### 自动验证

| 场景 | 通过标准 |
| --- | --- |
| 注册与旧账号登录 | 旧用户名、密码和 ID 不变；同机重复账号拒绝；跨机同名账号不自动合并 |
| 新申请与旧申请 | 新快照来源可靠；旧申请显示未记录；缺失快照不影响原有授权 |
| 成员与设备批准 | 新人需要批准；换电脑只能经明确选择绑定原成员；角色不自动继承 |
| 正常修改密码 | 新盐和哈希更新，新密码可登录，旧密码失败，当前账号全部旧会话失效 |
| 验证失败 | 未登录、错误旧密码、非法新密码、相同新旧密码和限流均无凭据、会话或业务数据副作用 |
| 事务失败 | 模拟审计或数据库写入异常，凭据、会话撤销和审计整体回滚 |
| 账号隔离 | 无法修改其他本地账号密码；其他账号会话、其他电脑账号和团队角色均不变 |
| 工作空间与并发 | 有在途受保护操作时拒绝修改；撤销后旧令牌不能产生新写入；不自动重放请求 |
| 离线与待同步数据 | 断网、共享盘不可达或同步暂停不阻止修改本地密码；本地队列、冲突和原文件保留 |
| 安全审计与打包 | 日志、共享 roster、业务备份和发布包中不出现密码、哈希或会话令牌 |
| 实验清理 | 无微软入口、认证 API、依赖和当前配置要求；旧 URL 不产生认证；旧审计不被删改 |
| 升级兼容 | 从已有 main 数据、v1.10.2 预发布数据分别打开后，账号、成员、历史和待同步状态保留 |

### 浏览器验证

使用独立模拟工作区，覆盖 English / 中文、普通桌面和约 390px 窄屏：

- 登录、注册、最近账号、重复账号、密码显示/隐藏、错误与提交中状态。
- 注册后连接团队、稍后设置、等待批准、拒绝、已批准与设备被撤销。
- 管理员审批新成员、明确绑定原成员，以及旧申请没有账号快照。
- 个人工作空间与相邻团队功能并排检查，修改密码表单、确认、成功重新登录和失败保留输入。
- 两个独立会话及普通多标签页；旧页面失效时能保存或复制尚未提交内容。
- 模拟响应丢失，展示结果不确定提示，不自动再次修改。
- 键盘顺序、表单标签、Enter 提交、Escape 关闭、焦点返回、减少动态效果。
- 切换语言不改变工作区域宽度，打开/关闭抽屉或对话框不移动底层页面。

复用 `src/theme.ts`、唯一 App ConfigProvider、`src/Refined.css`、现有 Ant Design 控件与消息提示；不增加新视觉系统、页面局部样式副本或认证运行时依赖。

完成上述检查仍不等于真实多电脑 SMB 验收，也不构成防止本地文件或共享目录被篡改的企业级身份认证承诺。
